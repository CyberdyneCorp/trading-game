# Tasks: add-run-sharing-and-journal-stats

Sections can be owned by parallel builders:
- **E (engine and fixtures)**: independent of the clients.
- **W (web)**: needs E1–E4.
- **D (desktop)**: needs E1–E4; mirrors W.

Each task ships its tests and updates the READMEs and this change in the same PR. A task is ticked only when it is fully done.

## E. Engine and shared fixtures

- [ ] E1 Move the golden action applier into `src/run_file.cpp` (`detail::apply_action`, the shared action format with client ids). `tests/golden.cpp` uses it, and every golden stays byte-identical.
- [ ] E2 Run file schema validation (design D1, D2): strict reader limits, every member and action checked, path of the first bad member, canonical output and SHA-256.
- [ ] E3 `tl_run_file_verify(file, pack, pack_len, keys)`:
  - policy check;
  - mission or pack run;
  - replay with the shared applier;
  - status and digest comparison;
  - the debrief when the run ended;
  - reason codes of D2;
  - a WASM export and `c_api.h` docs.

  `kAbiVersion` stays 1.
- [ ] E4 IDL shapes `RunFileVerdict` and `EngineTrade.stopMovedAway`; regenerated `idl_types.hpp`, `idl_schema.hpp` and `types.ts`; conformance test for both verdicts.
- [ ] E5 `stopMovedAway` on perpetual debrief trades (design D8), with tests for moved away, moved toward the entry, a take-profit moved and a short. No digest or version change.
- [ ] E6 `tests/test_run_file.cpp`:
  - a round trip of every scripted golden;
  - each tamper and malformed case;
  - limits;
  - a pack run;
  - a deterministic mutation fuzz loop (thousands of mutants: never crashes, accepts only canonical-equivalent files).

  It runs native and under WASM.
- [ ] E7 Shared fixtures `engine/tests/runfiles/` with `index.json` (design D9), generated by `tools/make_run_files.py` from the scripted goldens, embedded in the test binary and checked by the engine test.
- [ ] E8 Python binding `verify_run_file` (for a later server-side import); not needed by the clients.

## W. Web

- [ ] W1 `runFile.ts`:
  - build a run file from a run record and its actions (notes opt-in, decimals as strings);
  - file name;
  - size pre-check;
  - refusal texts per reason;
  - exporting runs on private packs refused.

  Unit tests include the shared fixtures through the WASM build in Node, and a check that the exporter writes the fixtures' canonical files from the goldens.
- [ ] W2 Worker `verifyRun` request (run-less), and the session's import: verify, ask for a missing catalog pack, store in the `imports` store (IndexedDB version 4), dedupe by `fileDigest`, remove.
- [ ] W3 Replay viewer (`replay.ts` stepping, the session's viewing mode, `ReplayScreen.svelte`):

  - the debrief without the player's controls;
  - leaving it keeps the resumable run;
  - every command path closed while viewing.
- [ ] W4 Export and import controls: debrief, journal and stats (export, with the plan-notes option); menu and journal (import, with the verdict).
- [ ] W5 Per-run summary on the run record at the debrief (`runSummary.ts`), and recomputation of older runs through verification.
- [ ] W6 `journalStats.ts` aggregation (design D7) and `JournalStats.svelte`: cards with lesson links, R distribution, risk bands, stops, liquidations, repeated mistakes, per mission and stage, trend, mission filter, small-sample warning. PT-BR and en.
- [ ] W7 E2E (`run-sharing.spec.ts`):
  - export a finished run, import it in a fresh browser context, step it bar by bar and open the debrief;

- [ ] W8 READMEs (root, `apps/web`, `engine`) and this change.
